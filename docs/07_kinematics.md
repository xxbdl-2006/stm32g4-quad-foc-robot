# 运动学与轨迹规划

这一层回答两个问题："四个关节转多少，末端在哪"（正解 / 逆解），以及
"怎么从这儿走到那儿才不会出事"（轨迹规划）。代码全部在
`ros2_ws/src/arm_control/`，实现见 `dh.cpp / scara_ik.cpp / trajectory.cpp`，
测试见 `test/test_arm_kinematics.cpp`（510 项检查，`test/run_host_test.sh` 可在
无 ROS、无 Eigen 的机器上直接跑）。

## 一、为什么用 D-H 参数表，而不是手写展开式

本机构三个回转轴都平行于 Z，正解当然可以直接手写成三角级数（代码里也确实
有一份，`forward_tool_pose`，热路径上用）。但机构的**描述**必须用 D-H 表：

- 改机构 = 改表，正解算法一行不动。换一根长一点的大臂、把升降轴从末端挪到
  中间，都只是改几个数；
- 逆解的推导也从表上读出来，不会出现"正解改了、逆解还按旧机构解"这种
  最阴的错；
- 表本身就能当文档用 —— 看一眼就知道机构长什么样。

标准 D-H（Craig 约定）的单级变换：

    i-1_T_i = Rz(θ_i) · Tz(d_i) · Tx(a_i) · Rx(α_i)

本机构的表（α 全为 0，因为三个回转轴互相平行 —— 这正是 SCARA 的定义）：

| i | θ_i | d_i | a_i | α_i | 说明 |
|---|-----|-----|-----|-----|------|
| 1 | θ1（变量） | d1 = 0.140 | a1 = 0.180 | 0 | J1 基座回转；d1 是台面到回转平面的高度，a1 是 J1→J2 轴 |
| 2 | θ2（变量） | 0 | a2 = 0.180 | 0 | J2 大臂回转；a2 是 J2→J3 轴 |
| 3 | θ3（变量） | 0 | a3 = 0.060 | 0 | J3 小臂回转；a3 是 J3 轴到吸盘中心 |
| 4 | 0（固定） | d4（变量，m） | 0 | 0 | J4 升降，直线轴 |

α = 0 的后果值得记住：末端姿态只有绕 Z 的旋转 θ1+θ2+θ3，俯仰/横滚恒为 0。
所以"把吸盘垂直压到物块上"是机构自带的，不需要姿态规划 —— 这是选 SCARA
做取放任务的核心原因。

正解的闭式结果（也是 `forward_tool_pose` 的实现）：

```
x   = a1·cosθ1 + a2·cos(θ1+θ2) + a3·cos(θ1+θ2+θ3)
y   = a1·sinθ1 + a2·sin(θ1+θ2) + a3·sin(θ1+θ2+θ3)
z   = d1 + d4
yaw = θ1 + θ2 + θ3
```

代码里矩阵链（`forward_kinematics`）与这个展开式**互相校验**：两者是刻意
分开写的，改了 D-H 表忘了同步展开式（或反过来），测试会立刻炸。这是
510 项检查里最重要的一条断言。

## 二、闭式逆解

本机构最后两级（J4 升降、末端吸盘）与 XY 平面解耦，前两级构成标准平面
2R 臂，因此存在解析解。相比牛顿迭代：

- 不会发散、不需要初值、迭代次数为 0；
- 能明确区分"无解"与"没收敛" —— 数值法给不出干净的布尔答案，而
  "目标不可达就跳过该物块"这个业务逻辑需要它；
- 100Hz 的规划周期里可以在同一周期解很多次（笛卡尔直线路径逐点求解）。

### 解的结构

给定末端位姿 (x, y, z, φ)：

1. **直线轴**：d4 = z − d1。与平面解完全解耦。
2. **腕心**：从末端沿 −φ 方向退回 a3，得到 J3 轴心的平面坐标
   `Pw = (x − a3·cosφ, y − a3·sinφ)`。
3. **平面 2R**：由 (a1, a2) 到 Pw 的两解（肘上 / 肘下）：
   `c2 = (|Pw|² − a1² − a2²) / (2·a1·a2)`，
   `θ2 = atan2(±√(1−c2²), c2)`，
   `θ1 = atan2(Pw.y, Pw.x) − atan2(a2·s2, a1 + a2·c2)`。
4. **补齐朝向**：θ3 = φ − θ1 − θ2。

### 两个解选哪一个

同一末端位姿有两组解（肘上/肘下）。选**与当前关节值距离最小**的那组，
而不是固定取"肘上"。原因：笛卡尔直线路径是逐点解逆解的，如果中途从一组
解跳到另一组，末端会在两点之间划出一条谁也没规划过的大弧线 —— 表现是
机械臂突然"甩"一下。测试里有一条专门的检查：沿直线追踪 41 个采样点，
相邻点的关节跳变必须小于 2°。

### 四种拒绝原因（各自有明确的物理含义）

| status | 含义 | 典型场景 |
|---|---|---|
| `OutOfReach` | 腕心超出 [a1−a2, a1+a2] 的环带 | 物块摆在台边或落在基座内孔里 |
| `LiftOutOfRange` | 目标 z 超出升降行程 | 高度参数填错 |
| `JointLimit` | 解存在但撞关节限位 | 目标在正后方，θ1 要转 190° 而限位是 ±180° |
| `Singular` | 接近奇异（\|sinθ2\| < sin3°） | 两臂接近共线，径向速度能力退化 |

奇异判据取 sin(3°)：对应腕心距离最大伸展只差 0.12mm —— 禁区窄到不影响
正常取放，但足以挡住"目标正好落在边界上时解出 θ2=0 然后满力矩硬顶"。

## 三、五次多项式（关节空间）

6 个系数正好对应 6 个边界条件（起点/终点的位置、速度、加速度）：

```
q(0)=q0   q̇(0)=v0   q̈(0)=a0
q(T)=q1   q̇(T)=v1   q̈(T)=a1
```

为什么不用梯形速度 / 三次多项式：

- 梯形速度的加速度在起停点是**阶跃**。阶跃加速度 = 阶跃力矩，而谐波减速器
  的柔性会把力矩阶跃激励成末端抖动。对"用吸盘吸一个 80mm 物块"的任务，
  末端在抓取点的残余抖动直接决定吸不吸得住；
- 三次多项式解决了加速度不连续，但落点加速度不可控，多段拼接时每个接缝
  的加速度都对不上，末端会"点头"；
- 五次多项式让多段轨迹拼起来是 **C² 连续**的。

零边界条件（起停都停稳）下，s(τ) = 10τ³−15τ⁴+6τ⁵ 有两个常数：

```
峰值速度   = 1.875   · |Δq| / T        （τ = 0.5 处）
峰值加速度 = 5.7735  · |Δq| / T²       （τ = (3±√3)/6 处，值 = 10/√3）
```

这两个数给出了"给定位移量、求最短可行时间"的**解析式**，不用迭代试：

```
T ≥ 1.875·|Δq|/vmax      （速度约束）
T ≥ √(5.7735·|Δq|/amax)  （加速度约束）
```

### 多关节时间同步

`synchronized_duration` 对所有关节取同一个 T（各关节所需时间的最大值）。
这一点必须强制：如果每个关节各自按自己的极限取时间，走得慢的关节会
"拖"着末端走出一条谁也没规划过的曲线，在狭窄的工作区里会撞到料框。
取最大值等于"最慢的关节决定节奏，其余关节降速配合"。

## 四、笛卡尔直线

接近、下压、抬升这些段要求**末端走确定的路径**：

- 下压段如果走弧线，吸盘会沿物块表面滑动，压在边缘上就吸空了 ——
  这是取放任务最常见的失败模式；
- 抬升时末端贴着物块，任何横向位移都会把它蹭倒。

`CartesianMove` 的做法：直线插值（路径参数 s∈[0,1]）+ 五次时间标定 +
逐点逆解（内部以上一次的解做种子，保证分支不跳变）。

**先规划、后执行**：`plan()` 阶段就沿路径探测 17 个点的逆解（同时验证
路径连续性），无解直接拒绝 —— 绝不允许运行到一半才发现，那时末端已经
悬在半空。

直线路径不可行（穿过基座内孔、超出工作半径）时，可以自动改成三段绕行：
**抬到安全高度 → 平移 → 下压**。下压/抬升段必须关掉绕行：这时末端离
物块只有几毫米，"抬起来再回来"反而更容易碰倒它。

### 时间标定的迭代校验

直线路径上的关节轨迹是"五次时间标定 ∘ 逆解"的复合，**不再满足**第三节的
那两条解析界。所以 `plan()` 会真的采样算一遍（200 点、中心差分），超限就
把总时长按超限比例放长重来，最多 5 轮 —— 收敛很快，因为关节速度大致与
T 成反比。

这里有个实打实的坑：加速度估计必须用**中心二阶差分**
`a_i ≈ (q_{i-1} − 2q_i + q_{i+1})/dt²`。一开始写的是 `a ≈ 2Δq/dt²`，
这个式子随 dt→0 **发散**（采样越密"算出来的加速度"越大），结果一条最简单的
竖直下压（只有 J4 在动、峰值加速度恰好压在上限）被判成超限一百多倍，
规划直接被拒 —— 表现为"机械臂拒绝做最普通的抬升动作"。测试抓出来后
连同推导一起写进了代码注释。

## 五、雅可比

`numerical_jacobian` 用前向差分（步长 1e-6）算 3×4 的位置雅可比。
解析雅可比对 RRPR 也不难写，但数值差分只有 8 次正解，换来的是
"改 D-H 表之后雅可比自动跟着对"。它用在两处：末端合成速度（给任务层的
停稳判据）、以及 `/arm/status` 上的 tool_twist。

末端速度用雅可比而不是末端位置差分：位置来自 100Hz 聚合话题，差分出来的
速度噪声比信号还大（1mm 位置抖动 ÷ 10ms = 0.1 m/s 的假速度），而停稳判据
的阈值就是 10mm/s 量级。

## 七、上机后还要核对的三件事

主机侧测试再全，也验不了**实物**的三个输入：

1. **D-H 表里的长度**。用卡尺量实机，对不上就改 `arm_model.hpp`（那是唯一
   真源），再同步 URDF 与 `hardware.yaml`；
2. **关节零位**。每个关节单独小速度点动，确认零位与方向（见 `05_tuning.md`
   第 5 节）；
3. **丝杠导程**。J4 走 100mm 应该对应丝杠整 10 圈 —— 量一下就知道导程参数
   对不对（丝杠标称 10mm，实际可能有 2% 的偏差，累积到 135mm 行程就是
   2.7mm，直接影响 touch_z 的过盈量）。
